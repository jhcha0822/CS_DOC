# FAQ: Memo/글 등록 동작 방식 및 권한 구조

## 1. H2에 Memo 관련 데이터가 없어도 글 등록·조회가 되는 이유

**요약: "글 등록"과 "메모"는 서로 다른 기능이며, 저장 테이블이 다릅니다.**

- **게시글 등록 (이미지의 "게시글 등록" 폼)**  
  - **Post** 엔티티 / **post** 테이블을 사용합니다.  
  - 카테고리 선택, 제목, 본문, 첨부파일 등으로 저장하며, **Memo 테이블과 무관**합니다.  
  - 따라서 H2에 **memo 테이블 데이터가 없어도** 게시글 등록·조회는 정상 동작합니다.

- **메모 (Memo)**  
  - **Memo** 엔티티 / **memo** 테이블을 사용하는 **별도 기능**입니다.  
  - 사이드바의 "메모" 메뉴에서 사용하는 데이터입니다.

- **정리**  
  - 게시글: `post`, `post_version` 등 Post 관련 테이블  
  - 메모: `memo` 테이블  
  Memo 데이터 유무는 게시글 등록·조회에 영향을 주지 않습니다.

## 2. MEMBERS 테이블과 권한 설정

**현재 구조**

- **members** 테이블에는 보통 다음과 같은 컬럼이 있습니다.  
  (실제 DB는 JPA 엔티티 기준으로 생성됩니다.)  
  - `id` (PK)  
  - `username` (로그인 아이디)  
  - `password` (암호화 저장)  
  - `name` (표시 이름)  
  - **`role`** (권한: `ADMIN`, `USER` 등)

- **권한(role)**  
  - **ADMIN**: 관리자 (실습 채점 조회, 카테고리 관리, 사용자 관리 등)  
  - **USER**: 일반 사용자  

- **추가 권한(피평가 대상 등)을 넣고 싶을 때**  
  - **방법 1**: `UserRole` enum에 값 추가 (예: `USER`, `ADMIN`, `EVALUEE` 등)  
  - **방법 2**: 역할은 두 개만 두고, "피평가 대상" 여부는 **별도 컬럼** (예: `boolean evalee`) 또는 별도 테이블로 관리  
  - DB에 role 컬럼이 있다면 `SELECT * FROM members` 시 `role` 값도 함께 조회해 현재 누가 ADMIN/USER인지 확인할 수 있습니다.
